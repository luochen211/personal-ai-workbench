# 派活 · 个人开发工作台

一个人同时管好几摊事时，消息散在 GitHub、微信群、录音和会议纪要里，大部分时间花在翻消息、记背景、转述需求上。派活把这些收进本机的一个页面，按「下一步该谁做」排好；该动手的交给 Agent 去做，要你拍板的才来找你。

它跑在你自己的电脑上，只绑定 127.0.0.1，数据不出本机。干活的 Agent 由 [agent-autoloop](https://github.com/KKKKhazix/agent-autoloop) 中台调度。

## 理想情况

**你不再去找事，事来找你。** 早上打开收件箱，看到的是已经分好类的几件事：谁在等你回、哪份草稿等你确认、哪个 PR 审完等你合。没变化的东西不出现，也不打扰你。

**你只做决定，不做转述。** 一条 issue 要改代码，勾上交给 Agent。它在单独的工作区改好、跑完测试、开 PR，另一个 Agent 单独审；审出问题它自己返工，返工三轮还不行才停下来问你。中途缺你定的事，它攒成一包一次问完，每一问都带推荐，你在一屏里点完就行。

**用你的名义说的话，都先经过你。** 回 GitHub 留言、开 issue、建仓库，Agent 只写草稿，你看过、改过、点了确认才发出去。发之前还会重读一遍讨论，对方刚好又回了，会先问你要不要改。

**群里随口说的需求不会丢。** 微信群、录音、会议纪要里提到的待办，它拟成一条条 issue 草稿放着；你挑出要做的，选好仓库，点一下就进了正常的流程。

**想问点什么，直接问。** 「对话」页里的助理能读你的仓库、工作台、GitHub 和中台，但什么都不改；你要改东西，它拟一张 issue 草稿给你确认。

**它记得你在做什么，也替你看着自己。** 每天早上有简报、有按你手上的事挑好的阅读；每周、每月自动复盘；它自己哪里没跑成，也会告诉你。

## 功能

### 收件箱：所有要你看的事，按下一步排好

- 把登记项目的 open issue、你开着的 PR 和 GitHub 通知合在一起，同一条 `owner/repo#编号` 只列一行。
- 按「下一步该谁做」分类：待你回、草稿待确认、待动手、待你看、Agent 处理中、等对方、我发的 PR、搁置、记录；底部是近 30 天做完的。
- 判断谁最后说话：对方真人的最后一句晚于你最后一个动作，才算待你回；机器人（CI、代码审查机器人）的留言不算。
- 维护者和路人分开标：留言人是 OWNER、MEMBER、COLLABORATOR 还是被请求的评审人，行上写明。
- 暂时不处理的事只记在本机，对方有新动静或到了你选的时间，自己回到列表里。
- 只管你最近真在做的项目：最近一个月有你本人提交（或你在上游开过 PR、issue）的项目才进范围，每天自动核对；你在别人仓库开过 PR、issue 的，会自动加进「开源协作」组。

### 交给 Agent：改代码、写回复

- **处理 issue**：自己的仓库打 `agent` 标签交出去；别人的仓库，有推送权限就在原仓库开分支，没有就 fork 到你的账号再开 PR。每条 issue 一个新工作区，不碰你本地正在改的代码。
- **回复留言**：「帮我回复」只写回复草稿；「处理并回复」先改代码，再写草稿。
- **处理 PR 反馈**：别人在你的 PR 上提了意见，交出去，Agent 逐条改好推回原分支，再给每条意见写好回复草稿。
- **批量交**：勾选一批一起交，一次最多 50 条，不适合交的会写明原因跳过。
- **一次问完**：缺你定的事整条做完后收成一个决定包。【问你】的等你定；【默认过】的已按推荐做了，你不改就算定了。代码里查得到的事不问。
- **不白跑**：上一轮已经有「要你定」或「不用动」的结论，之后又没有新动静的，不会再派一次。
- **看得见进度**：每条 issue 写着走到哪一步（已交给、处理中、审查中、返工第几轮、等你决定、等你看、已处理），详情里有 PR 链接和这一轮的结论。

### 审查和返工：写的和审的不是同一个

- Agent 开的 PR 由另一个独立的审查 Agent 审，审的是某一个具体提交，结论只有三种：通过、要改、等一等。
- 要改就自动返工，回到同一个分支和 PR 上改，改完再审；最多三轮，第四次还要改就停下来等你决定。
- 只审你本人开的、同一仓库分支上的 PR；别人的 PR 和 fork 来的不审，因为审查要在本机跑别人的代码。
- 审查卡住、CI 太久没出结果、PR 在审完之前就被合并了，都会提醒你一次，不会悄悄重来。
- Agent 永远不合并 PR，合不合由你定。

### 草稿：用你的名义发出去之前，都先给你看

- Agent 写的回复放在「草稿待确认」，你可以直接改，改完点「确认发送」才用你的账号发出。
- 发之前重读讨论；对方在这期间又回了，先问你要不要重写。
- 草稿发现这条其实要改代码，会建议你改用「处理并回复」重新交一次。

### 新需求：把群聊、录音里的需求拟成 issue

- 点「读新需求」，它读你登记过的微信会话，以及新的录音和会议转写（得到、飞书妙记、本机录音文件），把里面的待办和需求拟成 issue 草稿，一条一行。
- 录音也可以在页面上直接上传，在本机转写。
- 每条草稿你看过、改过、选好仓库（或新建一个私有仓库）再点创建；原话只留在本机，不写进 issue。
- 从草稿建的 issue 做完后，在 issue 下 @ 你填的那个 GitHub 账号，提需求的人会收到通知。

### 对话：只读的助理

- 在页面里和助理聊天，它能读你的助理文件夹和项目代码，查工作台、GitHub、中台的状态，回答「这件事卡在哪」「助理最近在做什么」这类问题。
- 它只能读，不能改：在沙箱里运行，不能写文件，只能执行一条只读的查询命令，也不读本机的个人设置。
- 你要改代码、改文档时，它不会自己动手，而是在回答末尾附一张 issue 草稿卡片；你点「存成草稿」，草稿才进「新需求」，确认后再走正常的交给 Agent 流程。
- 接了生财有术社区的只读查询：能搜帖子、案例、航海手册和精选内容，能看你自己的浏览足迹、划线和航海进度。打赏、点赞、收藏、发布这类写操作一个都不放行。
- **生财晨读**：每天早上，它先看你手上在推哪几件事、在生财上读过什么，再挑 2～4 篇推到你的飞书，每篇写清为什么现在适合读、对应你哪件事；读过的不推。想追问，就在对话页打开那条对话接着聊。

### 助理：简报、事项、学习、回顾、健康

- **今日简报**：今天要你定的事（最多 5 条）、收入和系统状况、收件箱和 Agent 的动静、日程和待办。
- **事项**：每摊事现在到哪了、下一步是什么、卡在谁那，Agent 每天自己记。
- **学习**：给一个题目，Agent 一篇篇写给你读。每篇末尾填学习反馈，点「写下一篇」，下一篇按你的反馈调整难度和角度。也能读本机的小说导读。
- **回顾**：每周日、每月 1 日自动生成：时间花在哪、合了多少 PR、下周最重要的 3 件事、三个反思问题。问题直接在页面上答。
- **健康**：读手环导出的睡眠、心率、步数，画成四张对齐的图，算出达标几晚、几点睡、最近一周比之前好还是差。

### 自媒体

- **麦田**：只读连接自媒体多平台发布中控 [麦田](https://github.com/CzzzzzzJ/mdldm-maitian)，看最近几期发到了哪些平台、哪些在等你点发布、各平台涨了多少粉、哪个平台登录失效了。
- **在做的内容**：每条内容做到哪一步、发没发。

### Agent：运行记录和巡检

- **运行记录**：中台每一轮干了什么、结论是什么、用了多久；正在跑的那一轮，时间每秒更新。
- **巡检状态**：中台和监看是不是正常、上次什么时候看过、下次什么时候复查。
- **省着用 GitHub**：监看要用的 GitHub 状态合成一个请求读，没变化就不叫醒中台。实测没有变化的日子，中台从每天 144 轮降到 24 轮兜底。

### 插件

- 可选功能做成插件，在页面的插件窗口里装、卸、检查；卸掉就停用，数据留着，也可以连数据一起删。
- **微信插件**：收件箱多一个「微信」范围，列出私聊待回、群里 @ 你的、待收转账，只读；「新需求」也能读登记过的微信群；还能查订阅的公众号推过哪些文章。

### 桌面提醒

Agent 要问你、做完了、监看连续出错时，弹一条可点的桌面通知，点一下直接打开工作台里对应的那条。工作台没开，就先在后台把它启动起来。

## 它不做的事

- 对 GitHub 的写操作只有五种：给自己仓库的 issue 打 `agent` 标签；发出你确认过的回复草稿；创建你确认过的 issue 草稿；你确认后为草稿新建私有仓库；从草稿建的 issue 做完后在 issue 下 @ 你填的账号。其余全是只读。
- Agent 不合并 PR，不直接发评论，不替你回消息。
- 不存 GitHub 凭据（由 `gh` 管），也不把微信原话、客户信息写进仓库或 issue。
